2. MAJOR ISSUES IDENTIFIED & ROOT CAUSES
--------------------------------------------------------------------------------
1. Character / Guide Naming Inconsistencies:
   - Root Cause: Slide 4 Card 7 originally contained a pill labeled "SAATHI CHARACTER", 
     erroneously implying the companion character's name was Saathi rather than Semmozhi.
   - Resolution: Corrected the pill on Slide 4 to "SEMMOZHI CHARACTER", widened the pill 
     container to prevent truncation, and updated Card 8 to explicitly state 
     "delivered by Semmozhi (virtual guide)". Verified consistent naming across all slides.

2. Broken Slide Numbering:
   - Root Cause: Slides 10 through 28 utilized an un-evaluated slide number field 
     (`<a:fld type="slidenum">`) with a stale cached text value of "20", causing 
     external viewers, PDFs, and slide exports to display "20 / 29" or "‹#› / 29". 
     Slide 1 and Slide 29 lacked page numbering entirely.
   - Resolution: Evaluated and hardcoded exact sequential page numbers "1 / 29" 
     through "29 / 29" on all 29 slides. Added high-contrast white footers to 
     Slide 1 and Slide 29.

3. Broken Indic Unicode & Script Shaping:
   - Root Cause: In the original file, Indic scripts were fragmented into single-character 
     runs with negative character kerning (`spc="-50"` to `-275`). This severed 
     OpenType ligatures and complex Devanagari/Tamil glyph shaping in Uniscribe/DirectWrite, 
     producing detached vowel signs (e.g., dotted circle "◌िहन्दी" and corrupted "தமÛழ்").
   - Resolution: Rebuilt multi-lingual strings as cohesive text runs assigned to the 
     standard Windows Indic font "Nirmala UI", correctly rendering:
     - English: "English" / "EN"
     - Hindi: "हिन्दी" (and spoken transcript "मुझे रेलवे स्टेशन नहीं मिल रहा")
     - Tamil: "தமிழ்"

4. Template & Placeholder Text:
   - Root Cause: Presentation contained unedited template placeholders (e.g., 
     "[Your Name]", "[Reg. No.]", "[Start date] → [End date]", "[number to be confirmed]").
   - Resolution: Replaced template strings with clean, academic fill-in fields 
     (e.g., "Name: __________ | Reg. No.: __________ | Dept.: __________") or 
     professional milestone wording, avoiding fabricated personal or empirical data.

5. Typographical & Grammatical Errors:
   - Root Cause: Inadvertent whitespace splits, missing spaces, and concatenated headings.
   - Examples Fixed:
     - "I t uses" → "It uses" (Slide 25)
     - "I t shows" → "It shows" (Slide 26)
     - "Understanding yourquestion…" → "Understanding your question…" (Slide 19)
     - "services (112)" space restored (Slide 28)
     - Broken numeric arrow "4" in workflow note restored to "→" (Slide 17)

6. Visual Layout & Element Clipping:
   - Titles on Slides 3, 10, 11, and 22 wrapped awkwardly onto two lines after em-dash 
     spacing or kerning removal. Adjusted text box bounds to maintain clean single-line headers.
   - Slide 4 Card 6: Re-balanced paragraph styles (bold title, regular body) to eliminate 
     collision with the bottom pill.
   - Slide 5 Card 6: Realigned typography, font size (12.5pt bold title, 11pt regular body), 
     and proper color hierarchy (#0F172A title, #475569 body).
   - Slide 7 Card 5 ("My Responsibilities"): Replaced awkward bold wall of text with clean, 
     aligned paragraphs matching the diamond-bullet layout of other cards.
   - Slide 19: Precisely centered individual language buttons ("English", "हिन्दी", "தமிழ்") 
     inside the Phone 2 graphical pills.
   - Slide 21: Re-sized safety disclaimer text inside Phone 1 yellow card to prevent 
     border overflow.
   - Slide 23: Re-balanced "Method" card typography so text stays neatly within card boundaries.
   - Slide 25: Fixed table header cell contrast so column headers ("Component", "What it does", 
     "Type") are crisp and legible.

4. ARCHITECTURE & REVIEWER WORKFLOW VERIFICATION
--------------------------------------------------------------------------------
The presentation strictly complies with the reviewer-mandated low-cost architecture:
  User Query → Query Processing / NLP → Identify Intent → Local Verified Travel Database → Retrieve Required Data → Semmozhi GUI (Text + Voice + Animation)

Technical Constraints Confirmed:
- No ChatGPT API, OpenAI API, Gemini API, or third-party cloud generative AI.
- Android Speech Recognition (RecognizerIntent) handles speech-to-text.
- Android TextToSpeech handles voice output.
- Android Location Services used exclusively for route assistance with user consent.
- Semmozhi character uses lightweight frame-based mouth animation / lip-sync.
- SOS triggers phone dialler / 112; trusted-contact alert clearly tagged as Future Scope.
